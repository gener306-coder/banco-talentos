# HU-S5-01 — Indicadores y avisos operativos en el inicio por rol

Estado: completada y verificada el 27 de octubre de 2026 (Fase 1: backend; Fase 2: interfaz).

## Alcance

Historia aprobada en `docs/sprint-5.md`, en dos fases:

- **Fase 1 (backend):** el endpoint `GET /api/dashboard` con los conteos de cada rol y sus pruebas Pest. No hay migraciones nuevas: se consultan las tablas existentes.
- **Fase 2 (interfaz, CA-07):** los contadores en la página de inicio (`SessionPage`), el aviso de «Municipio por confirmar» para `INSTITUTION` y el comportamiento ante fallos, con pruebas Vitest y Playwright.

Fuera de alcance: filtrar el padrón por «Municipio por confirmar» (el aviso enlaza al padrón completo) y actualizar los contadores sin recargar el inicio.

## Decisiones

| Tema | Decisión |
| --- | --- |
| Acceso (CA-01) | Ruta `GET /api/dashboard` con `auth:sanctum`, `active` y `role` con los cuatro roles. Una cuenta inactiva recibe `401` sin código; la de una institución o empresa inactiva, `401 INSTITUTION_INACTIVE` o `401 COMPANY_INACTIVE` (middleware `active`). No pasa por `institution.member`: una cuenta `INSTITUTION` sin institución recibe `200` con `metrics: null`, no `403`. |
| Solo conteos | La respuesta contiene únicamente el rol y números enteros. Ningún nombre, identificador ni dato de alumnos, organizaciones o cuentas. |
| ADMIN (CA-02) | Instituciones activas e inactivas con un solo `count(*) FILTER`. Las cuentas `SECRETARY` se separan en `active_secretaries` (`is_active` y ya configuraron su contraseña) y `pending_secretaries` (`is_active` y `password_setup_required`). Las inactivas no cuentan. |
| SECRETARY (CA-03) | Empresas activas e inactivas y las cuentas `SECRETARY` pendientes (misma definición que para ADMIN). |
| INSTITUTION (CA-04) | Todas las consultas filtran por `students.institution_id` de la sesión (anti-IDOR). `active_students`: alumnos con `is_active`. `searchable_students`: alumnos que cumplen la condición del buscador de HU-S4-05 (activo, los seis campos del expediente y el punto capturados); la institución está activa porque lo garantiza `active`. `pending_municipality_students`: alumnos activos o inactivos con `legacy_municipality` y sin `municipality_code`. |
| COMPANY (CA-05) | `available_talent_profiles`: el universo exacto del buscador (HU-S4-05 CA-02): alumno buscable de una institución activa. Una prueba compara el número con `meta.total` de `GET /api/talent` sin filtros. |
| Sin organización (CA-06) | Una cuenta `INSTITUTION` sin `institution_id` o `COMPANY` sin `company_id` recibe `metrics: null` sin ejecutar ninguna consulta de conteo. La cuenta `COMPANY` sin empresa solo puede existir en una base local anterior a HU-S4-03 (restricción `NOT VALID`). |
| Una sola condición de «buscable» | La condición del expediente completo se extrajo al scope `Student::searchable()`. `TalentController` (HU-S4-05) y `DashboardController` lo reutilizan, de modo que el buscador y el inicio no pueden desincronizarse. |

### Interfaz (Fase 2)

| Tema | Decisión |
| --- | --- |
| Ubicación | Región «Indicadores» (`section` con `aria-label`) entre la acción principal y las tarjetas de acceso. Cada indicador es un par `dt`/`dd` de una lista de definiciones (`.home-stats`): la cifra grande en acento y la etiqueta debajo, con el lector de pantalla leyendo primero la etiqueta. Cifras con separador de miles `es-MX`. |
| Cliente | `src/dashboard/api.ts` (`getDashboard`) valida la respuesta: el `role` debe ser el de la sesión y cada conteo del rol un entero no negativo; conserva solo las claves del rol. Cualquier otra forma se trata como `502`. |
| Sin organización (CA-06) | Si la cuenta no tiene organización vinculada, el inicio ya muestra el aviso de cuenta sin secciones y **no** consulta `/api/dashboard`. Si el servidor responde `metrics: null`, no se muestran indicadores ni error. |
| Aviso de municipio | Solo para `INSTITUTION` con `pending_municipality_students > 0`: «N alumnos tienen «Municipio por confirmar».» (singular con 1) con el enlace «Revisar el padrón» a `/students`. Reutiliza `.pending-notice` (tokens `--status-off-*`) de HU-S4-04: es un pendiente, no un error. |
| Fallo (CA-07) | Mientras carga no se muestra nada (sin esqueleto, para no desplazar las tarjetas). Si falla, un párrafo discreto «No pudimos cargar los indicadores…» sin `role="alert"`; las tarjetas y la acción principal siguen funcionando. Un `401` cierra la sesión como en el resto de la aplicación (`useApiRequest`). |
| Estilos | `ui.css` usa solo tokens semánticos (`--surface`, `--border`, `--text`, `--accent`); con `prefers-contrast: more` el borde de los indicadores pasa a `--border-strong`, igual que las tarjetas. |
| Pruebas existentes | Las pruebas que renderizan el inicio sin interés en los indicadores (`App`, `Institutions`, `CompaniesPage`, `TalentSearchPage`) dejan `/api/dashboard` pendiente para que no consuma sus respuestas simuladas en orden. |

## Contrato API

`GET /api/dashboard` — sin parámetros. Cabecera `Cache-Control: no-store, private`.

`200` según el rol de la sesión:

```json
{ "data": { "role": "ADMIN", "metrics": { "active_institutions": 0, "inactive_institutions": 0, "active_secretaries": 0, "pending_secretaries": 0 } } }
```

```json
{ "data": { "role": "SECRETARY", "metrics": { "active_companies": 0, "inactive_companies": 0, "pending_secretaries": 0 } } }
```

```json
{ "data": { "role": "INSTITUTION", "metrics": { "active_students": 0, "searchable_students": 0, "pending_municipality_students": 0 } } }
```

```json
{ "data": { "role": "COMPANY", "metrics": { "available_talent_profiles": 0 } } }
```

Cuenta `INSTITUTION` o `COMPANY` sin organización vinculada:

```json
{ "data": { "role": "INSTITUTION", "metrics": null } }
```

Errores: `401` sin sesión o con la cuenta inactiva (`{message}`), `401 {message, code}` con `code` `INSTITUTION_INACTIVE` o `COMPANY_INACTIVE`.

## Cobertura de aceptación

Pest: `backend/tests/Feature/DashboardTest.php`. Vitest: `src/dashboard/api.test.ts` y `src/pages/SessionPage.test.tsx`. E2E: `e2e/home-dashboard.spec.ts`.

| Criterio | Verificación |
| --- | --- |
| CA-01 | Pest: visitante `401`; cuenta inactivada tras el login `401` sin código; institución inactiva `401 INSTITUTION_INACTIVE`; empresa inactiva `401 COMPANY_INACTIVE`; los cuatro roles reciben `200` con `Cache-Control: no-store, private`. |
| CA-02 | Pest: conteos exactos de instituciones activas e inactivas y de cuentas `SECRETARY` activas y pendientes; las inactivas no cuentan. |
| CA-03 | Pest: conteos exactos de empresas activas e inactivas y de cuentas `SECRETARY` pendientes. |
| CA-04 | Pest: conteos exactos con alumnos activos, inactivos, incompletos, con municipio por confirmar y ya confirmados; alumnos de otra institución (activa o inactiva) nunca alteran ningún conteo; institución sin alumnos recibe ceros. |
| CA-05 | Pest: excluye alumnos inactivos, incompletos, sin punto y de instituciones inactivas; coincide con `meta.total` del buscador. E2E: «Perfiles disponibles» coincide con el total que recibe el buscador sin filtros. |
| CA-06 | Pest: cuenta `INSTITUTION` sin institución recibe `200` con `metrics: null`. Vitest: sin organización no se consulta `/api/dashboard`; con `metrics: null` no hay indicadores ni error; el cliente acepta `metrics: null`. |
| CA-07 | Vitest: contadores de los cuatro roles en orden y con separador de miles; aviso en singular y plural con enlace a `/students` y sin aviso con 0; con un `500` o una respuesta de otro rol, aviso discreto sin `alert` y las tarjetas navegan; el cliente rechaza conteos faltantes, negativos, decimales o como texto. E2E: la institución ve sus contadores y «Alumnos activos» sube en 1 al registrar un alumno sin expediente, sin cambiar «Visibles en el buscador»; el aviso enlaza al padrón; con `/api/dashboard` respondiendo `500` el inicio sigue navegable. |
