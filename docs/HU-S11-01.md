# HU-S11-01 — Autocompletar del catálogo en el filtro de habilidades

Estado: completada y verificada el 12 de noviembre de 2026.

## Alcance

Historia aprobada en `docs/sprint-11.md`. El filtro de habilidades del buscador de talento (`/talent`) era un campo de texto libre: «pyhton» o «js» devolvían cero resultados. Ahora usa el `SkillPicker` del CV y de las oportunidades en un modo «solo catálogo», de modo que el error se corrige al capturar el filtro y el backend no adivina nada.

## Comportamiento

| Lo que escribe la empresa | Sugerencia | Enter |
| --- | --- | --- |
| «react» (`match: "prefix"`) | React, preseleccionada | La agrega como filtro. |
| «js» (`match: "alias"`) | JavaScript, preseleccionada | Agrega JavaScript, no «js». |
| «pyhton» (`match: "fuzzy"`) | Python, sin preseleccionar | No agrega nada y pide elegir una sugerencia. Se elige con las flechas o el ratón. |
| Texto sin sugerencias | Ninguna | No agrega nada y muestra el mismo mensaje. |
| Una habilidad ya elegida | No se vuelve a sugerir | «Esta habilidad ya está en la lista.» |

Enter nunca lanza la búsqueda; la búsqueda se lanza con **Buscar**. **Limpiar filtros** también vacía lo que se estaba escribiendo.

## Decisiones

| Tema | Decisión |
| --- | --- |
| Modo `catalogOnly` | Una propiedad del `SkillPicker`. Quita la opción «Agregar como nueva» y el selector de tipo, y muestra las etiquetas en una sola lista «Habilidades requeridas», sin separar técnicas y blandas: un filtro no registra habilidades. |
| Reglas de HU-S10-02 | Se heredan sin cambios: se preselecciona por prefijo o alias y nunca una sugerencia aproximada. |
| Enter sin sugerencia elegida | Muestra «Elige una habilidad de las sugerencias: solo se filtra por habilidades del catálogo.» El mensaje es el mismo si las sugerencias aún no llegan, para no afirmar que la habilidad no existe. |
| Filtros como nombres | `TalentFilters.skills` sigue siendo una lista de nombres y la API recibe `skills[]` igual que antes. El tipo que exige el picker se rellena con un valor fijo que este modo no muestra. |
| Atajo del inicio | La habilidad que llega desde el inicio de la empresa se aplica igual que antes, sin pasar por el picker. |
| CV y oportunidades | Sin cambios: `catalogOnly` es `false` por defecto y siguen permitiendo habilidades nuevas (CA-04). |

## Archivos

- `frontend/src/students/SkillPicker.tsx`: propiedades `catalogOnly` y `label`; `contactMessage` y `placeholder` pasan a ser opcionales.
- `frontend/src/talent/TalentSearchPage.tsx`: usa el picker en el filtro de habilidades.
- `frontend/src/talent/talent.css`: se quitan los estilos del campo anterior.

## Cobertura de aceptación

Vitest: `src/talent/TalentSearchPage.test.tsx`. Las pruebas del picker en `src/students/StudentCvPage.test.tsx` y `src/opportunities/OpportunitiesPage.test.tsx` siguen pasando sin cambios. Playwright: `e2e/talent-search.spec.ts`.

| Criterio | Verificación |
| --- | --- |
| CA-01 | «js» sugiere JavaScript por alias, queda `aria-selected` y Enter la agrega. «pyhton» sugiere Python sin preseleccionarla. |
| CA-02 | No existe el grupo «Tipo para una habilidad nueva» ni la opción «como nueva». Enter con «pyhton» o con un texto sin sugerencias muestra el mensaje y no agrega la etiqueta. |
| CA-03 | Enter agrega la habilidad sin llamar a `/api/talent`. Una habilidad ya elegida no se repite. La etiqueta se quita con su botón. Los filtros enviados incluyen `skills[]=React`. |
| CA-04 | Las pruebas del CV y de las oportunidades no cambiaron y pasan. |
| CA-05 | Las pruebas anteriores. En E2E la empresa escribe la habilidad en minúsculas, la elige de las sugerencias del catálogo real y encuentra el perfil. |
