# HU-S16-04 — Recuperación de emergencia por consola

Estado: completada y verificada el 22 de noviembre de 2026.

## Alcance

Historia aprobada en `docs/sprint-16.md`. Antes, nadie podía restablecer la contraseña de un Administrador ni corregir su correo. Ahora tres comandos de consola, auditados como acciones del servidor (D3), lo resuelven sin intervenir la base de datos a mano.

## Contrato

- **`admin:list`:** tabla con id, nombre, correo, estado (Activa o Inactiva), contraseña (Configurada o Pendiente de configurar) y fecha de alta. Nunca muestra hashes ni tokens. Sin Administradores, sugiere `admin:bootstrap`.
- **`admin:reset-password {email} {--manual}`:** solo para cuentas `ADMIN` activas.
  - Emite el enlace de `/reset-password`, de 60 minutos y un solo uso. A una cuenta pendiente de configurar le emite de nuevo su enlace de `/set-initial-password`.
  - Borra todas sus sesiones, rota `remember_token` e invalida los enlaces del otro tipo.
  - Avisa con `ResetInstitutionPassword::CONSOLE_INITIATOR`, o imprime el enlace con `--manual`.
  - Registra `password_reset_issued` con `actor_kind = cli`.
- **`admin:update-email {actual} {nuevo}`:** solo para cuentas `ADMIN` (D4).
  - Valida el formato, que el correo no esté registrado y que sea distinto del actual.
  - Invalida los enlaces pendientes, que están ligados al correo anterior, y cierra las sesiones.
  - Avisa con `AccessEmailChanged` a la dirección anterior y a la nueva.
  - Registra `email_changed` con `["email"]`, sin los valores.

## Decisiones

| Tema | Decisión |
| --- | --- |
| Cuenta inactiva | No se restablece. Primero hay que reactivarla en Cuentas de Administración (HU-S16-02). Si no queda ningún Administrador activo, `admin:bootstrap` vuelve a estar disponible. |
| La contraseña vigente | El restablecimiento no la anula: cierra las sesiones y emite el enlace, igual que el restablecimiento iniciado por Administración. El aviso lo dice. |
| Logs | Solo `user_id`, el tipo de enlace y el medio de entrega; nunca el token, la URL ni los correos. |
| Código compartido | El trait `FindsAdministrator` bloquea la cuenta con `FOR UPDATE` y cierra el acceso con la misma lógica que el cambio de contraseña (HU-S14-01). |

## Cobertura de aceptación

| Criterio | Cobertura |
| --- | --- |
| CA-01 `admin:list` | Muestra las cuentas ADMIN y su estado; excluye otros roles y no muestra hashes; sugiere el arranque si no hay ninguna. |
| CA-02 `admin:reset-password` | Enlace emitido; sesiones de esa cuenta cerradas (otras intactas); token rotado; tokens de configuración invalidados; aviso de consola; evento `cli`; el enlace establece una contraseña nueva e inicia sesión; `--manual` sin el token en los logs; cuenta pendiente con su enlace de configuración; rechaza otros roles, correos inexistentes y cuentas inactivas sin efectos. |
| CA-03 `admin:update-email` | Cambio con sesiones cerradas, enlaces invalidados y avisos a ambas direcciones; evento sin valores; entra con el correo nuevo y no con el anterior; rechaza correos inválidos, ocupados o iguales y cuentas que no son ADMIN. |
| CA-04 Bitácora de consola | Migración y vista en HU-S16-01. |
| CA-05 Pruebas | Las anteriores. |
