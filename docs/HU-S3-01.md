# HU-S3-01 — Expediente Profesional (CV Normalizado)

Estado: implementada y verificada el 16 de octubre de 2026 en dos fases: backend y pruebas Pest (`5e8127b`), e interfaz con Vitest y E2E.

## Alcance

Implementación de la historia aprobada en `docs/sprint-3.md`: un CV con el mismo formato para cualquier disciplina (titular, habilidades, idiomas, certificaciones, proyectos y enlaces), estructurado para que las empresas filtren en el futuro, con los enlaces y las credenciales protegidos hasta un match.

Fuera de alcance: el buscador de las empresas y el «match» (Sprints futuros). Ver «Reglas para el futuro buscador».

## Decisiones (aprobadas por el responsable)

| Tema | Decisión |
| --- | --- |
| Modelo (CA-03) | Tablas relacionales, no JSONB: los niveles de idioma se filtran por rango (`level >= 4`), el planificador tiene estadísticas por columna para combinar filtros, y las FK y los `CHECK` garantizan la integridad. Cada índice empieza por la columna filtrada. |
| Habilidades | Catálogo abierto y compartido (`skills`) con `slug` único normalizado: minúsculas, sin acentos y con espacios simples, conservando `#`, `+` y `.` («C#», «C++» y «Node.js» no colapsan). **El tipo (técnica o blanda) lo fija el catálogo**: quien la registra primero lo elige y se respeta al reutilizarla. Las altas usan `INSERT … ON CONFLICT DO NOTHING`, seguro ante dos instituciones que la crean a la vez. |
| Idiomas | Lista corta ampliable de 22 idiomas con clave ISO 639-1 (`CvLanguage`); la columna admite tres letras para crecer. Nivel entero: A1=1 … C2=6, Nativo=7 (`LanguageLevel`). |
| Certificaciones (CA-04) | Sin integración API con Credly (su API es para emisores). `credential_id` y `credential_url` se guardan en la zona protegida, porque la página de verificación muestra el nombre del alumno. `verifiable` marca las URLs de plataformas conocidas (`config/cv.php`). La institución, actor de confianza, puede marcarlas como **revisadas** (`verified_at`, `verified_by`). |
| Revisión al editar | Cambiar el nombre, el emisor, las fechas o la credencial de una certificación revisada pone `verified_at` y `verified_by` en `null`. Guardarla igual (aun con otros espacios) o cambiarla de posición conserva la revisión. |
| Anonimato (CA-02) | `student_links` y `student_certification_credentials` son tablas protegidas (`COMMENT` de datos protegidos). La API separa `public` de `protected`. Además, el texto libre público (titular, habilidades, certificaciones y proyectos) rechaza URLs, correos, teléfonos y dominios: `http(s)://`, `www.`, `@` con dominio, 10 o más dígitos con separadores y TLD de una lista corta (`.com`, `.mx`, `.io`, `.dev`, `.org`, `.app`, `.me`), para no confundir «Node.js», «Vue.js» o «ASP.NET». |
| URLs | Solo `https` con dominio público: sin IP, `localhost`, dominios reservados (`.local`, `.internal`, `.test`…), puertos, credenciales ni espacios. GitHub, LinkedIn y Behance deben ser de su dominio o un subdominio (`mx.linkedin.com`); un dominio parecido (`github.com.evil.io`) se rechaza. El servidor nunca abre las URLs. |
| Guardado | Por sección: cada `PUT` reemplaza su sección completa en una transacción. Las certificaciones se actualizan por `id` (debe ser del alumno; uno ajeno responde `422` «La certificación no existe.» sin tocarlo) y las omitidas se borran con su credencial (cascada). |
| Anti-IDOR | `FindsOwnedStudent` en todas las rutas; la revisión además exige que la certificación sea del alumno (`404` «La certificación no existe.»). Todas las tablas usan la FK compuesta `(student_id, institution_id)`. |

### Reglas para el futuro buscador

- Leer solo `students` y las tablas públicas del CV; nunca `student_identities`, `student_social_security`, `student_links` ni `student_certification_credentials`, salvo tras un match autorizado.
- Filtrar `students.is_active = true` (HU-S2-04).
- Un `EXISTS` por filtro, como en la prueba de CA-03, para aprovechar los índices.
- La respuesta para empresas debe ser un Resource con lista explícita de campos públicos, sin `verified_by` (nombre del personal de la institución).

## Modelo de datos

Migración `2026_10_16_000001_create_student_cv_tables`. Aplícala en desarrollo con `docker compose exec backend php artisan migrate`.

| Tabla | Columnas | Índices y restricciones |
| --- | --- | --- |
| `students.headline` | varchar(120), nulo | — |
| `skills` | `name` (80), `slug` (80, único), `kind` | `CHECK kind`; `skills_slug_prefix_index` (`text_pattern_ops`) para autocompletar por prefijo |
| `student_skills` | `student_id`, `institution_id`, `skill_id`, `position` | PK `(student_id, skill_id)`; índice `(skill_id, student_id)` |
| `student_languages` | `student_id`, `institution_id`, `language_code` (3), `level`, `position` | PK `(student_id, language_code)`; índice `(language_code, level, student_id)`; `CHECK` código `^[a-z]{2,3}$` y nivel 1–7 |
| `student_certifications` | `name` (150), `issuer` (120), `issuer_slug`, `issued_on`, `expires_on`, `verified_at`, `verified_by` (FK `users`), `position` | Índice `(issuer_slug, student_id)`; `CHECK` vigencia ≥ emisión y `verified_by` solo con `verified_at` |
| `student_projects` | `title` (120), `description` (1000), `role` (80), `year`, `position` | — |
| `student_links` *(protegida)* | `kind`, `url` (2048), `position` | Único `(student_id, lower(url))`; `CHECK kind` |
| `student_certification_credentials` *(protegida)* | `certification_id` (PK), `credential_id` (120), `credential_url` (2048), `verifiable` | FK `(certification_id, student_id, institution_id)` a la certificación con borrado en cascada; `CHECK` al menos uno de los dos datos |

Todas las tablas del alumno tienen la FK compuesta `(student_id, institution_id)` → `students(id, institution_id)`.

## Contrato API

Mismo grupo que el resto de alumnos (`auth:sanctum`, `active`, `role:INSTITUTION`, `institution.member`), mismo patrón de identificador y `Cache-Control: no-store, private`. Todas las rutas de escritura responden el CV completo.

| Método y ruta | Cuerpo |
| --- | --- |
| `GET /api/students/{id}/cv` | — |
| `PUT …/cv/headline` | `{headline}`; `null` o vacío lo borra |
| `PUT …/cv/skills` | `{skills: [{name, kind}]}`, máximo 30; una repetida se guarda una vez |
| `PUT …/cv/languages` | `{languages: [{language_code, level}]}`, máximo 10, sin repetir idioma |
| `PUT …/cv/certifications` | `{certifications: [{id?, name, issuer, issued_on, expires_on?, credential_id?, credential_url?}]}`, máximo 20 |
| `PATCH …/cv/certifications/{certification}/verification` | `{verified: true \| false}` (booleano estricto); marcar una ya revisada conserva quién y cuándo |
| `PUT …/cv/projects` | `{projects: [{title, description, role?, year?}]}`, máximo 10; sin campo de URL |
| `PUT …/cv/links` | `{links: [{kind, url}]}`, máximo 10, sin repetir URL |
| `GET /api/skills?q=` | Hasta 10 habilidades del catálogo por prefijo literal (`%` y `_` no son comodines) |

Respuesta:

```json
{"data": {
  "public": {"headline": "…", "skills": [{"id", "name", "kind"}], "languages": [{"language_code", "level"}],
             "certifications": [{"id", "name", "issuer", "issued_on", "expires_on", "verified_at"}],
             "projects": [{"id", "title", "description", "role", "year"}]},
  "protected": {"links": [{"id", "kind", "url"}],
                "credentials": [{"certification_id", "credential_id", "credential_url", "verifiable"}],
                "reviews": [{"certification_id", "verified_by"}]}
}}
```

Cada elemento solo admite sus claves (`array:…`): un campo extra, como `url` en un proyecto, responde `422`. Errores: `401` sin sesión o con institución inactiva, `403` para otros roles o cuentas sin institución, `404` para alumnos ajenos o inexistentes, `419` sin CSRF.

## Cobertura de aceptación (Pest, `StudentCvTest`: 147 pruebas)

| Criterio | Verificación |
| --- | --- |
| CA-01 | Titulares de varias disciplinas; habilidades técnicas y blandas en orden; idiomas con MCER y Nativo; certificaciones; proyectos; enlaces de los cuatro tipos; reemplazo y vaciado de cada sección; límites y validaciones de cada campo sin escrituras. |
| CA-02 | Enlaces y credenciales solo en `protected`; tablas públicas sin columnas de URL ni credencial; `COMMENT` de datos protegidos; el padrón y el detalle no contienen enlaces ni credenciales; detector de contacto (13 casos detectados y 10 falsos positivos evitados, como «Node.js», «ASP.NET», «C#», «Python 3.12» o «ISO 9001:2015») en titular, habilidades, certificaciones y proyectos. |
| CA-03 | Índices que empiezan por la columna filtrada; consulta cruzada «inglés ≥ B2, React y certificación Cisco» sobre seis perfiles que devuelve exactamente los dos que cumplen (mayúsculas de «react» y «CISCO» normalizadas; B1, sin React, sin Cisco y solo francés quedan fuera). |
| CA-04 | Credencial por id o URL; `verifiable` para Credly y Microsoft Learn, no para otros dominios; revisión con autor y fecha, idempotente; anulación al editar cada campo revisado (siete casos) y conservación si no cambia; `404` para revisar certificaciones de otro alumno; booleano estricto. |
| Seguridad | URLs inseguras (16 casos: `http`, `javascript:`, IPv4, IPv6, IP privada, `localhost`, `.internal`, puerto, credenciales, sin TLD, espacios, dominios de otro tipo y parecidos); catálogo: reutilización por slug con el tipo del catálogo, símbolos, autocompletar por prefijo literal con límite; `404` ajeno o inexistente en las siete rutas sin escrituras; identificadores mal formados; matriz de roles; visitante, cuenta sin institución e institución inactiva; CSRF en cada sección; FK compuesta y `CHECK` en la base. |

## Interfaz (fase 2)

Página propia **CV profesional** en `/students/:id/cv` (ruta protegida para `INSTITUTION`), enlazada desde el detalle del alumno con una píldora bajo su nombre. Carga el alumno y su CV en paralelo; un alumno ajeno o inexistente muestra «El alumno no existe.». Cada sección se guarda por separado, con validación en línea igual a la del servidor, botón con estado pendiente que impide envíos duplicados, errores del servidor junto a su campo y aviso de guardado junto al botón.

| Sección | Interacción |
| --- | --- |
| Titular profesional | Campo con contador de 120 caracteres; rechaza datos de contacto. |
| Habilidades | Etiquetas («chips») removibles agrupadas en técnicas y blandas. Combobox accesible (`role="combobox"`, `aria-activedescendant`) que consulta `GET /api/skills?q=` 200 ms después de dejar de escribir (cancela la búsqueda anterior); flechas para moverse, Enter para agregar, Escape para cerrar. Las sugerencias excluyen lo ya elegido y ofrecen «Agregar «…» como nueva» con el tipo elegido; una del catálogo conserva su tipo. Evita duplicados (mismo slug) y datos de contacto. |
| Idiomas | Filas idioma + nivel (A1 … C2, Nativo); evita repetir idioma y exige el nivel. |
| Certificaciones | Fichas con nombre, emisor, fechas y estado **Revisada** / **Sin revisar** (con quién y cuándo). **Marcar como revisada** y **Quitar revisión** usan el `PATCH`. Alta y edición en una hoja (inferior y arrastrable en móvil, panel centrado en escritorio, con scrim); al editar una revisada avisa que la revisión se quitará. La credencial aparece en la ficha con un candado y el enlace se abre con `rel="noopener noreferrer nofollow"`. Eliminar pide confirmación (`ConfirmDialog`). |
| Proyectos | Fichas; alta y edición en una hoja con contador de la descripción; sin campo de URL y con la nota de que los enlaces van en la sección protegida. Eliminar pide confirmación. |
| Enlaces externos | Sección con la insignia **Protegido** y la nota «Esta información no es visible en la búsqueda general de empresas». Filas tipo + URL que validan https público y el dominio de GitHub, LinkedIn y Behance; evita enlaces repetidos. |

Estilos en `ui/ui.css` con los tokens de `docs/design/identidad-visual.md` y los principios de apple-design: etiquetas tintadas (técnicas con `brand-primary`, blandas con `brand-secondary`), lista de sugerencias que se materializa, fichas, insignias de revisión y de protección con el icono de candado (`LockIcon`), filas que se apilan a 600 px, y la `Sheet` existente (seguimiento del dedo, impulso y resistencia en el borde). Los `fieldset` de las hojas ya no muestran el borde del navegador.
