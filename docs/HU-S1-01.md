# HU-S1-01 — Autenticación y control de acceso

Estado: implementada y verificada el 27 de septiembre de 2026.

## Alcance entregado

Login, identidad y logout con Laravel Sanctum para SPA, sesiones en servidor y protección CSRF. React conserva la identidad sólo en memoria; no guarda credenciales en localStorage ni sessionStorage. La sesión se regenera al autenticar y se invalida al cerrar sesión.

Los roles reconocidos son ADMIN, INSTITUTION, COMPANY y SECRETARY. En esta entrega todos disponen únicamente de autenticación, consulta de identidad y logout. No existen módulos de negocio, registro público ni permisos específicos de módulos. El middleware de roles valida el rol persistido en backend y exige coincidencia explícita, sin privilegios implícitos de ADMIN.

## Criterios de aceptación

| Criterio | Resultado | Evidencia automatizada |
| --- | --- | --- |
| CA-01: acceso con credenciales correctas y cuenta activa | Cumple | Pest autentica los cuatro roles con cookies reales; E2E completa el login. |
| CA-02: rechazo genérico de credenciales incorrectas | Cumple | Pest compara la respuesta para correo desconocido, contraseña incorrecta y cuenta inactiva; React y E2E comprueban el mensaje. |
| CA-03: rutas frontend protegidas | Cumple | Vitest y E2E comprueban redirección a login para visitantes y después de logout. |
| CA-04: endpoints API protegidos | Cumple | Pest y E2E verifican 401, también sin Accept JSON; cookies de orígenes no configurados y tokens Bearer no autentican. |
| CA-05: invalidación después de logout | Cumple | Pest y E2E intentan reutilizar la cookie anterior al cierre de sesión y reciben 401. |
| CA-06: contraseñas almacenadas mediante hash | Cumple | Pest verifica creación y actualización con hash y ausencia de contraseña en la respuesta de identidad. |
| CA-07: autenticación API con Sanctum | Cumple | Rutas protegidas con auth:sanctum, statefulApi y sesión web; pruebas de CSRF, cookies y recuperación de sesión sin actingAs. |
| CA-08: cuatro roles y alcance limitado | Cumple | Enum y esquema con los cuatro valores; pruebas de login/identidad para cada rol; no hay endpoints de módulos. |
| CA-09: autorización en backend | Cumple | Pest cubre las 16 combinaciones de roles, peticiones anónimas, rol falsificado y cambios de rol o estado activo durante una sesión. |
| CA-10: errores controlados | Cumple | Cobertura de respuestas JSON 401/403/419/422/429 y manejo frontend de errores y fallos de red. |

Las rutas restringidas a un rol usadas para probar CA-09 se registran sólo dentro de Pest. No añaden funcionalidades de negocio a la aplicación.

| Frontend: `npm run lint` y `npm run build` | Aprobados. |
| Backend: `composer lint` y `composer validate --strict` | Aprobados. |
| Validación de ambos archivos Compose, sintaxis de scripts y `git diff --check` | Aprobadas. |

El E2E detectó durante el desarrollo que Laravel intentaba redirigir a una ruta login inexistente si el cliente no solicitaba JSON. Se corrigió esa configuración y se añadieron regresiones para Accept vacío, */* y text/html. Las ejecuciones finales de Pest y E2E quedaron aprobadas.

Los scripts de pruebas utilizan bases, sesiones, claves y contenedores independientes de desarrollo. Las credenciales E2E se generan de forma efímera. Los contenedores y la red de pruebas fueron eliminados al terminar; sólo se conserva el volumen de dependencias. Los scripts deben ejecutarse secuencialmente.

## Estado local y pendientes

La migración de usuarios está aplicada en desarrollo y los servicios locales permanecen activos. No se crearon cuentas predeterminadas. Para utilizar la interfaz, crea la primera cuenta de forma interactiva:

```bash
docker compose exec backend php artisan auth:create-user
```

Abre <http://localhost:5173> y utiliza una cuenta marcada como activa. El comando solicita la contraseña de forma oculta y sólo funciona en el entorno local.

No quedan tareas de implementación pendientes dentro del alcance autorizado. La validación E2E se realizó en Chromium; otros navegadores y despliegue de producción no formaron parte de esta entrega.
