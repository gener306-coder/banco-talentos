# HU-S16-01 — Arranque seguro del primer ADMIN

Estado: completada y verificada el 22 de noviembre de 2026.

## Alcance

Historia aprobada en `docs/sprint-16.md`. Antes no había forma de crear un Administrador en producción: `auth:create-user` solo corre en local y de forma interactiva. Ahora el primer Administrador se crea desde la consola del servidor, sin ninguna ruta pública (D1).

## Contrato

`php artisan admin:bootstrap {email} {--name=} {--manual}`

- **Validación:** normaliza el correo (minúsculas, sin espacios) y valida su formato y su longitud. El nombre es opcional, hasta 120 caracteres; sin nombre, la cuenta usa el correo como nombre provisional (M3).
- **Bloqueos:**
  - se niega con un `ADMIN` activo;
  - `pg_advisory_xact_lock` serializa dos arranques simultáneos;
  - un correo ya registrado falla sin crear nada.
- **La cuenta:** `ADMIN` activa, con `password_setup_required` y `created_by` nulo.
- **El enlace:** el de `/set-initial-password` (`InitialPasswordLink`, 60 minutos, de un solo uso).
  - Por correo, con el aviso `SetInitialPassword`.
  - Con `--manual`, se imprime una sola vez en la terminal.
  - `Log::notice` registra solo el `user_id` y el medio de entrega, nunca el token ni la URL.
- **La bitácora:** evento `admin_bootstrapped` con `actor_kind = cli` y `actor_id` nulo (D3). `/api/audit-events` lo devuelve con `actor: null`, y la vista muestra «Consola del servidor · Comando de operación».

## Base de auditoría (D3, D8)

La migración `2026_11_22_000001_add_console_actor_to_account_audit_events`, compartida con HU-S16-02 y HU-S16-04:

- `actor_id` nullable y `actor_kind` (`user` o `cli`), con `CHECK ((actor_kind = 'user' AND actor_id IS NOT NULL) OR (actor_kind = 'cli' AND actor_id IS NULL))`;
- el CHECK de `event` suma `admin_bootstrapped`, `password_reset_issued`, `email_changed` y `account_status_changed`.

`AccountAuditEvent::recordFromConsole()` es el único camino para los eventos sin cuenta. `record()` sigue exigiendo una cuenta.

## Decisiones

| Tema | Decisión |
| --- | --- |
| Configuración con enlace | `InitialPasswordController::issuable` admite `ADMIN` sin organización. La restricción `users_role_organization` ya impide que un `ADMIN` pertenezca a una organización. La prueba heredada que rechazaba al `ADMIN` se reescribió para verificar esa garantía. |
| Correo fallido | La cuenta queda creada y el comando indica emitir el enlace con `admin:reset-password --manual` (HU-S16-04). |
| Producción | El comando no exige un entorno local ni interacción, a diferencia de `auth:create-user`, que se conserva para desarrollo. |
