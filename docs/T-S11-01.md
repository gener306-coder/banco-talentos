# T-S11-01 — Refinamiento UI/UX de filtros y autocompletado

Estado: completada y verificada el 13 de noviembre de 2026.

## Alcance

Tarea aprobada en `docs/sprint-11.md` tras la auditoría de UI/UX del Sprint 11. La lista de sugerencias no respondía al cursor y las etiquetas de habilidades apenas lo hacían. Se agregan estados interactivos, transiciones y señales de claridad al `SkillPicker`, a los campos y al buscador de talento. No cambia ningún contrato de la API.

## Decisiones

| Tema | Decisión |
| --- | --- |
| Cursor y teclado separados | `:hover` solo pinta `--fill`; no mueve la opción activa. Enter sigue tomando únicamente la activa, así que una sugerencia aproximada bajo el cursor no se agrega por accidente (HU-S10-02). |
| Texto secundario | El tipo de la habilidad usa tamaño menor, peso normal y opacidad 0.9. Con 0.8 el contraste en el tema claro bajaba de 4.5:1. No se creó `--text-muted`. |
| «¿Quisiste decir?» y alias | Una sugerencia `fuzzy` lleva la nota «¿Quisiste decir?». Una `alias` lleva lo escrito («js»): la API no devuelve el alias, pero una coincidencia por alias es exacta, así que es el texto escrito. |
| «Sin coincidencias en el catálogo» | Aparece cuando el catálogo ya respondió a lo escrito y no hay nada que ofrecer. Mientras la respuesta no llega no se muestra, para no afirmarlo antes de tiempo. En el CV y las oportunidades casi nunca se ve, porque siempre existe la opción «Agregar como nueva». |
| Etiqueta nueva | Entra con opacidad y escala (180 ms). Solo las removibles (`.chip:has(.chip-remove)`): las de las tarjetas de resultados no se animan. La salida no se anima. |
| «X» siempre visible | Atenuada al 70 % y al 100 % con cursor o foco. No se oculta hasta el cursor porque en táctil no existiría. Conserva el color de acento: quitar un filtro no es destructivo (T-S8-16). |
| Botón dentro de la etiqueta | `.chip-remove` es un `button` y heredaba la sombra y la escala de los botones de acción. Se anulan para ese botón. |
| Foco y Retroceso | Al quitar una habilidad, con el botón o con Retroceso, el foco vuelve al campo. Retroceso solo actúa con el campo vacío. |
| Filtros sin aplicar | El buscador compara los parámetros que enviaría el borrador con los aplicados (`searchParams`). Si difieren, el botón dice «Aplicar filtros» y muestra un punto. Un texto con solo espacios o un origen sin municipio no cuentan como cambio. |
| Movimiento reducido | Con `prefers-reduced-motion: reduce`: la lista de sugerencias usa `fade-in` (antes seguía con escala y desenfoque), las etiquetas no se animan, y no hay escala al presionar ni elevación de la tarjeta. Los cambios de color se conservan. |
| Alcance global | Los estilos de `.chip`, `.combobox-list` y los campos están en `ui.css` y aplican a toda la aplicación: CV, oportunidades, selector de municipio y buscador. |

## Archivos

## Cobertura de aceptación

Vitest: `src/talent/TalentSearchPage.test.tsx`. Playwright: `e2e/talent-search.spec.ts`. Los estados visuales (cursor, transiciones y movimiento reducido) son CSS y no tienen prueba automática; requieren validación visual.

| Criterio | Verificación |
| --- | --- |
| CA-01, CA-02 | Validación visual pendiente del responsable. Sin prueba automática. |
| CA-03 | «JS» muestra JavaScript con la nota «js». «pyhton» muestra Python con «¿Quisiste decir?». Un texto sin resultados muestra «Sin coincidencias en el catálogo». |
| CA-04 | Quitar con el botón deja el foco en el campo. Retroceso con texto no quita nada; con el campo vacío quita la última habilidad. |
| CA-05 | El botón dice «Buscar» al cargar, «Aplicar filtros» con la clase `talent-pending` al editar, y vuelve a «Buscar» al aplicar o al deshacer los cambios. En E2E la empresa aplica los filtros con ese botón. |
| CA-06 | `src/ui/tokens.test.ts` pasa; no se agregaron tokens ni colores directos. |
| CA-07 | Vitest, ESLint, build y E2E pasan. |
