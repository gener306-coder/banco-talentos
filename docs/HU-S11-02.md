# HU-S11-02 — Resolución de alias exactos en el filtro `skills[]`

Estado: completada y verificada el 12 de noviembre de 2026.

## Alcance

Historia aprobada en `docs/sprint-11.md`. `GET /api/talent` comparaba cada habilidad de `skills[]` solo contra el `slug`. Ahora cada término nombra también a las habilidades que lo tienen como alias (T-S10-01), sin búsqueda difusa.

## Contrato

`skills[]` no cambia de forma: hasta 10 nombres. Cambia qué habilidades nombra cada uno.

| Término | Habilidades que nombra | Resultado |
| --- | --- | --- |
| `React` | La del slug `react` | Alumnos con React, como antes. |
| `js` | JavaScript (alias) y, si alguien la registró, la habilidad «JS» (slug) | Alumnos con cualquiera de ellas. |
| `bd` | Modelado y Normalización de bases de datos (alias en ambas) | Alumnos con cualquiera de las dos. |
| `bd` y `js` | Un grupo por término | Alumnos con alguna de `bd` **y** alguna de `js`. |
| `pyhton`, `javasc` | Ninguna | Cero resultados, sin consultar alumnos. |
| `java` | Solo Java | No trae a quien solo tiene JavaScript. |

La respuesta, la privacidad y el orden son los de HU-S4-05.

## Decisiones

| Tema | Decisión |
| --- | --- |
| `SkillCatalog::resolve()` | Recibe los términos ya normalizados y devuelve una lista de ids por término, en el mismo orden. Una sola consulta sobre `skills`: `slug IN (…)` o `aliases @> '["término"]'` por cada término. |
| Solo exacto | Sin prefijos, trigramas ni Levenshtein. `SkillCatalog::search()` es de autocompletar y ensancharía el filtro: «java» traería JavaScript. La tolerancia a errores vive en el picker (HU-S11-01). |
| Slug y alias a la vez | Si un término es el slug de una habilidad y el alias de otra, nombra a las dos. El catálogo semilla lo impide entre sus habilidades, pero una cuenta puede registrar «JS»; ambas significan lo mismo para quien busca. |
| OR y AND | Un `whereExists` por término con `skill_id IN (…)`, sobre el índice `student_skills (skill_id, student_id)`. Los términos se combinan con AND, como antes. |
| Término desconocido | Devuelve cero resultados sin consultar alumnos, como antes (CA-03). |

## Archivos

- `backend/app/Support/SkillCatalog.php`: método `resolve()`.
- `backend/app/Http/Controllers/TalentController.php`: `applyFilters()` usa `resolve()`.

## Cobertura de aceptación

Pest: `tests/Feature/TalentSearchTest.php`.

| Criterio | Verificación |
| --- | --- |
| CA-01 | «js» y «JS» traen a quienes tienen JavaScript (alias) y a quien tiene la habilidad «JS» (slug). «j» no es «js». |
| CA-02 | «bd» trae a quien tiene Modelado o Normalización. «bd» con «js» trae solo a quien cumple ambos grupos. «bd» con Python, que nadie combina, no trae a nadie. |
| CA-03 | «pyhton» y «javasc» devuelven cero. «js» con una habilidad inexistente devuelve cero. |
| CA-04 | Las pruebas de privacidad, tarjeta y orden de HU-S4-05 pasan sin cambios. |
| CA-05 | Las pruebas anteriores, más «java» que no trae a quien solo tiene JavaScript. |
